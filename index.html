Concept to console, in seven stages

01

Stage 01 / 07Concept

It starts as a sketch.

Every game starts as a question on a sticky note. What's the loop? What should the first ten seconds feel like? I keep each idea small on purpose, so the build that comes out of it proves one thing well.

Stage 02 / 07Prototype

Grey boxes, fast.

Before anything looks good, it has to play well. Controllers, core loops and game feel go in first, built data-first with ScriptableObjects so designers can tune without me.

Gameplay systems

Stage 03 / 07Polish

Then it gets a soul.

Runtime rigs, IK, blend shapes and procedural layers bring characters to life, and in-engine cinematics get cut with Cinemachine and Timeline. This is the pass where a prototype starts to feel like a game.

Animation & cinematics

  • Animation Rigging
  • Mecanim
  • Cinemachine
  • Timeline

Stage 04 / 07Systems

Code that thinks.

Behavior trees for NPCs that read the situation, pick a target and adapt, instead of walking a script. Plus the editor tools that take repetitive work off the team: custom windows, validators and automation.

Game AI

  • Behavior Trees

Stage 05 / 07Online

Built to be played together.

Synchronised gameplay on Photon, with KCC for networked character movement that still feels responsive under lag. Behind it, the server side a live game depends on: REST APIs, accounts, leaderboards and saves.

Multiplayer

    About

    The person behind the builds.

    I'm a Unity developer based in Gurugram. I started with 2D platformers in 2020 and have since worked on mobile games, a hub app that hosts over a hundred of them, XR fitness and training apps, and multiplayer on Photon.

    Most of what I do sits where the game meets everything around it: editor tools that remove busywork, WebGL builds that load quickly, pipelines that ship without hand-holding. Lately I've been pushing further into the server side, the APIs, auth and services a live game depends on.
